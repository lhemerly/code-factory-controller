# Opt-in native research cycle host

`scripts/spark-continuous.mjs` is a reusable host for approved research projects;
the filename is historical. Configure project ID, goal, repository, integration
ref and trusted checks explicitly. The default identifiers retain compatibility
with earlier SPARK configurations; no project, data or service configuration is
bundled or activated here.

OpenCode2.0.29 owns inference, tools and native children. Code Factory owns each
job, lease, grant, worktree, independent checks, receipts and recovery. Native
"done" and worker prose cannot accept a candidate or complete a scientific goal.
A separate whole-goal scientific contract decides clear-win completion. See
[the foreground dispatcher](research-dispatch.md) for one-slot coordination.

The host selects only active/enabled built-in OpenCode models with explicit zero
input/output/cache prices in every tier, preferring Big Pickle. Request hooks
recheck prices. Per-model denial/capacity circuits persist; no paid fallback exists.
Inconclusive results and rejected candidates feed another useful experiment or
negative control. Productive native work and its owned background shells have no
fixed elapsed or iteration cutoff; ownership and resource checks remain active.
Genuine permission, ownership and resource failures stop safely.

Each cycle uses its own immutable controller configuration, private native profile,
database and delivered archive. The Linux bubblewrap boundary mounts the worktree
and private profile writable and runtime/plugin/source/data read-only; Git control,
plugin-discovery paths and frozen inputs are protected. The operator token stays
outside the worker boundary. Network access required by approved inference remains
available, so this is not an exfiltration firewall for hostile code. Configure
appropriate external resource and network controls for the workload; a foreground
host does not install a service or enforce systemd CPU/memory limits.

Failed attempts require a positively confirmed owned stop and process cleanup
before replacement; uncertainty remains fenced. Previous unknown accounting stays
unknown. Native usage/cache counters are provider observations, not invoices.
Candidate repairs remain explicitly unaccepted until exact-commit verification.
The original protected-path baseline prevents repair bases absorbing forbidden edits.

Ctrl+C/TERM asks the host to fence and clean up its owned native work. A restart
reconciles completed handoffs without replay and refuses uncertain active state.
Optional desktop notifications and local event files are not scheduled model-driven
watchers or guaranteed cloud delivery. No unattended/24-hour readiness is claimed.
